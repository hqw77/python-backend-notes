# 教程文档排版规范

> 适用于 `mysql_notes/chNN/notes/` 下的每一章,以及 `mysql_notes/extras/notes/` 下的番外。
> 本文描述的格式是经过多轮调整后定稿的形态,新增章节请照此编写。

## 1. 为什么用这套格式

读者是"边学边理解"的自学者,有三个真实卡点:

| 卡点 | 表现 | 应对 |
| --- | --- | --- |
| 概念看不懂 | 术语堆叠,读完不知道在说什么 | 每个关键概念后加一个「通俗理解」注解 |
| 看完不会用 | 懂了概念,写不出来 | 每个知识点都对应一个可运行案例 |
| 忘了查不到 | 回头找某个参数要翻全文 | 编号章节 + 章末小结,便于定位 |

**核心原则:正文用教材写法保证准确,注解用白话保证看懂,案例保证能动手。**

---

## 2. 章节骨架

```plain
x.1  学习目标

x.2 ~ x.N  知识点
    x.N.1  概念 / 数据模型
    x.N.2  定义方法 / 语法
    x.N.3  示例与运行结果
    x.N.4  使用说明 / 对比分析
        └ 关键处插入「通俗理解」注解
        └ 每个示例标注对应的案例文件路径

x.N+1  常见错误
x.N+2  本章小结
x.N+3  练习
```

### 各部分要求

| 部分 | 要求 |
| --- | --- |
| 学习目标 | 4~6 条编号项,说明"学完能做到什么",并列出前置知识 |
| 知识点 | 三级编号(`5.3.2` 这种),按"概念 → 语法 → 示例 → 说明"顺序 |
| 通俗理解 | 用 `> **通俗理解**:` 开头的引用块,一到三句话,必须用生活场景打比方 |
| 案例引用 | 写成 `示例文件:`mysql_notes/ch05/code/01_relationship.py`` |
| 示例与运行结果 | 贴**真实运行输出**,不是手写的示意 |
| 常见错误 | 表格:`错误信息 / 原因 / 解决方法` |
| 本章小结 | 5~6 条编号要点,可直接当复习清单 |
| 练习 | 4 题,最后一题是思考题 |

## 3. 正文与注解的分工

**正文**(教材语言,保证准确):

> `add()` 把对象加入 Session 的 `new` 集合,`commit()` 执行 INSERT 并提交事务。

**注解**(白话,保证看懂):

> **通俗理解**:`add()` 像把商品加入购物车——车里有记录了,但还没下单,所以没有订单号。`commit()` 才是点"提交订单"。

判断标准:

- 能写进教科书、经得起推敲的 → 正文
- 帮人第一次理解、可以不严谨的 → 注解

## 4. 写作规则

| # | 规则 | 原因 |
| --- | --- | --- |
| 1 | 单章 300~550 行 | 超过 550 行说明该拆番外 |
| 2 | 正文不贴长代码,单个代码块 ≤ 20 行 | 长代码放案例文件,正文只留关键片段 |
| 3 | 每个示例必须标注案例文件路径 | 读者能立刻跑 |
| 4 | 运行结果必须是真实输出 | 编的示例会误导 |
| 5 | 每个知识点最多 2 个「通俗理解」 | 注解过密会让正文失焦 |
| 6 | 案例必须能独立运行,且自带数据清理 | 读者可以反复跑 |
| 7 | 术语首次出现给出中英文对照 | 如 `relationship(关系映射)` |
| 8 | **代码严格英文标点**:`.py`/`.sql` 中不允许出现中文标点,包括注释、docstring、字符串字面量 | 当前实测 0 处;换算后必须 `py_compile` 全量校验 |
| 9 | **文档保留中文标点**:`.md` 正文用 `。`、`、`、`(`、`)` 等,只有逗号统一用英文 `,` | 中文长句用英文句号读起来生硬;这条别"顺手"改 |
| 10 | 目录名不与已安装的包同名 | 用 `mysql_notes/`、`redis_notes/`、`fastapi_notes/`,避免遮蔽 `import redis` 这类语句 |
| 11 | 改完标点必须跑一遍全量验证 | `py_compile` 全部 `.py` + 跑案例 + `alembic check`,防止引号把语法改坏 |
| 9 | **代码注释与 docstring 里的所有标点用英文** | `：`→`:`、`。`→`.`、`（`→`(`、`、`→`,` 等;字符串里的业务文案不动 |
| 10 | 目录名不与已安装的包同名 | 用 `mysql_notes/`、`redis_notes/`、`fastapi_notes/`,避免遮蔽 `import redis` 这类语句 |

## 5. 已废弃的写法

以下格式曾用过,现已统一废弃,不要再用:

| 废弃项 | 曾用于 | 废弃原因 |
| --- | --- | --- |
| 六块结构(知识/案例/业务场景/排错/自测/速查卡) | 第 3~6 章初版 | 结构过重,读者反映"看不懂" |
| 比喻地图 + 英文词小抄 | 第 3~6 章第二版 | 表格太多,反而增加阅读负担 |
| 章首"分几次学"表 | 第 2~3 章 | 与编号章节功能重叠 |
| 每个案例的「改一改」 | 第 2~4 章 | 任务散落在正文里,不如统一放练习 |
| 面试题满分模板 | 第 3~6 章 | 偏应试,不适合日常学习 |
| 章末速查卡 | 第 2~4 章 | 与"本章小结"重复 |

## 6. 交付方式

| 场景 | 做法 |
| --- | --- |
| 新写一章 | 先给"知识点清单 + 目录",确认后写正文 |
| 改一章 | 只改结构不动结论,改完给出前后对比 |
| 新增案例 | 落一个 `mysql_notes/chNN/code/xx_yyy.py`,正文里标注路径 |
| 内容过长 | 主线留正文,细节拆到 `mysql_notes/extras/notes/` |

## 7. 检查清单

写完一章,逐条确认:

- [ ] 有 `x.1 学习目标`,且列出前置知识
- [ ] 所有小节都是三级编号
- [ ] 每个知识点后至少一个「通俗理解」
- [ ] 每个示例都标了案例文件路径
- [ ] 运行结果与案例实际输出一致
- [ ] 有常见错误表、本章小结、练习
- [ ] 正文无中文逗号(其余中文标点保留)
- [ ] 配套的 `.py` 案例无任何中文标点
- [ ] 案例跑过一遍,输出与正文一致
- [ ] 相对链接可跳转
