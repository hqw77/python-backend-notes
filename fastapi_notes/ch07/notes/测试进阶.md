## 7.2 dependency_overrides：把真依赖换掉

### 7.2.1 用法

```python
app.dependency_overrides[get_db] = lambda: {"db": "fake-dict"}
...
app.dependency_overrides.clear()      # 用完必须清
```

`app.dependency_overrides` 是一张"依赖 → 替代实现"的表，FastAPI 在解析 `Depends` 时会先查这张表。

案例文件：`fastapi_notes/ch07/code/01_dependency_overrides.py`

```plain
--- ① 没有覆盖: 用的是真依赖 ---
    {'db': {'db': 'real-mysql'}, 'user': {'user': 'real-user'}}

--- ② 只覆盖 get_db, get_user 保持原样 ---
    {'db': {'db': 'fake-dict'}, 'user': {'user': 'real-user'}}

--- ④ 清空覆盖, 恢复原状 ---
    {'db': {'db': 'real-mysql'}, 'user': {'user': 'real-user'}}
```

**只覆盖指定的那个依赖**，其他不受影响——这是它比"改全局配置"更好的地方。

### 7.2.2 三个典型用途

| 场景 | 覆盖什么 | 好处 |
| --- | --- | --- |
| 跳过登录 | `get_current_user` | 不用真的注册+登录+拿令牌 |
| 跳过数据库 | `get_db` | 不依赖 MySQL 是否启动 |
| 测试错误分支 | 某个必然抛异常的依赖 | 不用构造极端数据 |

案例实测：项目里 `/auth/me` 正常要令牌（401），覆盖后直接 200：

```plain
tests/test_overrides.py::test_me_with_overridden_user PASSED
tests/test_overrides.py::test_override_cleared_after_test PASSED
```

第二个用例专门验证"覆盖被清掉了"——**这比测试本身更重要**，因为漏清会污染后面的所有测试。

### 7.2.3 必须放在 finally 里清

```python
app.dependency_overrides[get_current_user] = lambda: FakeUser()
try:
    ...
finally:
    app.dependency_overrides.clear()
```

写成 fixture 更省事：

```python
@pytest.fixture
def fake_user():
    app.dependency_overrides[get_current_user] = lambda: FakeUser()
    yield
    app.dependency_overrides.clear()
```

## 7.3 三种测试隔离方式

### 7.3.1 问题

测试会改数据。跑完不还原，第二次跑就失败——**测试必须能重复跑**。

### 7.3.2 三种做法对比

| 方式 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| **自己清理** | 测试结束 `delete` 造的数据 | 简单直观 | 漏一处就留垃圾，要用 `try/finally` |
| **事务回滚** | 改完 `rollback`，不提交 | 最快 | 要求被测代码和测试共用同一个 Session |
| **独立测试库** | 连 `learn_mysql_test` | 最干净 | 建库建表，初始化慢 |

当前项目用的是**第一种**（`temp_user` fixture 里 `finally` 删除）。

### 7.3.3 事务回滚的原理

案例文件：`fastapi_notes/ch07/code/02_transaction_rollback.py`

```plain
--- ② 在事务里改, 但不提交 ---
    事务内读到:   788.00
    另一个 Session:  888.00 (看不到改动)
    → 未提交的改动只有当前事务能看到

--- ③ 回滚: 改动全部丢弃 ---
    回滚后本事务读: 888.00
    另一个 Session:  888.00
```

**隔离级别在这里起了作用**：未提交的改动对别的连接不可见，回滚后连自己都看不到了。

> **通俗理解**：事务像草稿纸，写错了揉掉就行；自己清理像用铅笔写正式文件，擦不干净会留印子。

## 7.4 parametrize：一个函数测多组输入

### 7.4.1 不用 parametrize 的样子

```python
def test_username_too_short(client): ...
def test_phone_too_short(client): ...
def test_phone_not_start_1(client): ...
def test_password_too_short(client): ...
```

四份几乎一样的代码。

### 7.4.2 用 parametrize

```python
@pytest.mark.parametrize(
    "payload, expected_field",
    [
        ({"username": "a", ...}, "username"),
        ({"username": "ab", "phone": "123", ...}, "phone"),
        ({"username": "ab", "phone": "23800000000", ...}, "phone"),
        ({"username": "ab", "phone": "13800000000", "password": "123"}, "password"),
    ],
    ids=["username-too-short", "phone-too-short", "phone-not-start-1", "password-too-short"],
)
def test_register_validation(client, payload, expected_field):
    r = client.post("/auth/register", json=payload)
    assert r.status_code == 422
    fields = [err["loc"][-1] for err in r.json()["detail"]]
    assert expected_field in fields
```

`ids=` 让失败信息可读：`test_register_validation[phone-not-start-1]`。

### 7.4.3 项目里补的测试

| 文件 | 内容 |
| --- | --- |
| `tests/test_validation.py` | 4 组注册校验 + 2 组负余额 + 3 组分页边界，共 9 个参数化用例 |
| `tests/test_overrides.py` | 覆盖 `get_current_user` + 验证覆盖被清掉 |

```plain
43 passed
```

## 7.5 测试文件的组织

```plain
project/tests/
├── conftest.py            # fixture: client / temp_user
├── test_auth.py           # 认证 8 个
├── test_cache.py          # 缓存 5 个
├── test_pagination.py     # 分页 + 排序 7 个
├── test_middleware.py     # 请求 id / 耗时 5 个
├── test_background.py     # 后台任务 2 个
├── test_openapi.py        # 契约 5 个
├── test_overrides.py      # 依赖覆盖 2 个
└── test_validation.py     # 参数化校验 9 个
```

**按"被测对象"分文件**，不按"测试类型"分。这样改一个功能，就知道该看哪个文件。

## 7.6 常见错误

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 后面测试突然 401 | 前面的测试覆盖了依赖没清 | `finally` 里 `clear()` |
| 第二次跑就失败 | 测试留了脏数据 | fixture 里清理，或用回滚 |
| `parametrize` 报参数数量不符 | 参数名个数和元组长度不一致 | 数一遍 |
| 失败信息看不出是哪组 | 没写 `ids=` | 加上可读的 id |
| 测试之间顺序影响结果 | 共享了可变状态 | 每个测试自己准备数据 |
| 测试很慢 | 每个用例都真的连库/登录 | 用 override 跳过 |

## 7.7 本章小结

1. `dependency_overrides` 可以把任意依赖换成假的，**只影响被覆盖的那个**。
2. 覆盖之后必须 `clear()`，否则污染后面的测试——最好用 fixture 包住。
3. 三种隔离方式：自己清理（当前用法）、事务回滚（最快）、独立测试库（最干净）。
4. 未提交的改动对其他连接不可见，所以 `rollback` 能干净地撤销。
5. `parametrize` 把多组输入写成一个函数，`ids=` 让失败信息可读。
6. 测试按"被测对象"分文件，比按"测试类型"分更好维护。
7. 项目测试从 32 个涨到 **43 个**，覆盖了认证、缓存、分页、中间件、后台任务、契约与校验。
