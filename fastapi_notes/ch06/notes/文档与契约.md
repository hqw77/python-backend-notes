# FastAPI 第六章 · 文档与契约

## 6.1 学习目标

FastAPI 会自动生成 `/docs`，但"有文档"和"文档能用"是两回事。这一章讲：

1. `/docs` 里的内容是从哪来的
2. 怎么定制标题、分组、参数说明
3. 为什么 `raise` 出来的错误在文档里看不到
4. 怎么用 `responses=` 把错误格式写进契约
5. 怎么用测试保证"文档不骗人"

前置知识：`mysql_notes` 第六章（schema）、第二章（`X-Request-ID`）。

---

## 6.2 `/docs` 是从哪生成的

FastAPI 把三样东西汇总成一份 OpenAPI 描述：

| 来源 | 内容 |
| --- | --- |
| 装饰器参数 | `tags` / `summary` / `description` / `response_model` / `responses` |
| 函数签名 | 参数类型、`Query(...)` 的约束与描述 |
| Pydantic 模型 | 请求体和响应体的 JSON Schema |

案例文件：`fastapi_notes/ch06/code/01_openapi_customize.py`

```plain
--- ② 接口怎么分组(tags) ---
    GET   /items             tags=['商品'] summary=商品列表
    GET   /items/{item_id}   tags=['商品'] summary=商品详情

--- ③ 查询参数自动带上描述和校验 ---
    page   类型=integer 说明=页码,从 1 开始
    size   类型=integer 说明=每页条数
    schema 里的约束: {"type": "integer", "maximum": 50, "minimum": 1,
                     "description": "每页条数", "default": 10}
```

**注意 `maximum: 50`**——`Query(le=50)` 的约束自动进了文档，前端不用猜上限。

### 6.2.1 响应模型变成 schema

```plain
--- ④ 响应模型自动变成 schema ---
    ItemOut: {"properties": {"id": {...}, "name": {...}},
              "required": ["id", "name"]}
```

`response_model` 不仅裁剪输出，还告诉文档"这个接口返回什么结构"。

## 6.3 错误响应：文档的盲区

### 6.3.1 问题

```python
@app.get("/items/{item_id}")
def get_item(item_id: int):
    if item_id > 100:
        raise HTTPException(status_code=404, detail="商品不存在")
```

```plain
--- ⑤ 但错误响应不会自动出现 ---
    已声明的响应码: ['200', '422']
    → 只有 200 和 422, 404 是代码里 raise 的, 文档里看不到
```

**为什么**：FastAPI 只能自动推断两类响应——

- `200`：由 `response_model` 推出
- `422`：由参数校验自动产生

`raise HTTPException(404)` 是运行时行为，FastAPI 不会去读代码里的 `raise` 语句。

### 6.3.2 后果

前端照着文档生成代码，只处理了 200 和 422。上线后遇到 404 直接懵。

> **通俗理解**：文档是一份合同，合同上没写的条款，对方不认。

## 6.4 用 `responses=` 补上契约

### 6.4.1 定义统一错误模型

```python
class ErrorResponse(BaseModel):
    detail: str = Field(description="错误说明")
```

### 6.4.2 在路由上声明

```python
@app.get(
    "/items/{item_id}",
    response_model=ItemOut,
    responses={
        404: {"model": ErrorResponse, "description": "商品不存在"},
        409: {"model": ErrorResponse, "description": "数据冲突"},
    },
)
```

案例文件：`fastapi_notes/ch06/code/02_error_contract.py`

```plain
--- ① 现在文档里能看到 404 了 ---
    200: Successful Response schema={'$ref': '#/components/schemas/ItemOut'}
    404: 商品不存在        schema={'$ref': '#/components/schemas/ErrorResponse'}
    409: 数据冲突         schema={'$ref': '#/components/schemas/ErrorResponse'}
    422: Validation Error schema={'$ref': '#/components/schemas/HTTPValidationError'}
```

### 6.4.3 契约必须和真实返回一致

```plain
--- ② 声明的错误格式必须和真实返回一致 ---
    真实返回: 404 {'detail': '商品不存在'}
    → {detail: ...} 和 ErrorResponse 对上了, 契约没撒谎
```

如果文档写 `{detail: str}`、实际返回 `{msg: str}`，前端按文档写 `r.data.detail` 永远拿到 `undefined`。**这种"文档骗人"比没文档更糟。**

## 6.5 在项目里落地

### 6.5.1 新增 `app/schemas/error.py`

```python
class ErrorResponse(BaseModel):
    detail: str = Field(description="错误说明")

RESP_400 = {400: {"model": ErrorResponse, "description": "参数不合法"}}
RESP_401 = {401: {"model": ErrorResponse, "description": "未认证"}}
RESP_403 = {403: {"model": ErrorResponse, "description": "没有权限"}}
RESP_404 = {404: {"model": ErrorResponse, "description": "资源不存在"}}
RESP_409 = {409: {"model": ErrorResponse, "description": "资源冲突"}}
```

把常用的声明做成常量，路由里直接 `responses=RESP_404`，不用每次手写。

### 6.5.2 三个接口挂上

| 接口 | 声明 |
| --- | --- |
| `GET /users/{id}` | 404 |
| `POST /users` | 409 |
| `POST /auth/login` | 401 |

实测文档：

```plain
  /users/{user_id}     声明的响应: ['200', '404', '422']
  /users               声明的响应: ['201', '409', '422']
  /auth/login          声明的响应: ['200', '401', '422']
  ErrorResponse 在 schemas 里: True
```

### 6.5.3 用测试保证契约

`project/tests/test_openapi.py`，5 个用例：

| 用例 | 验证 |
| --- | --- |
| `test_error_schema_registered` | `ErrorResponse` 进了 schemas |
| `test_user_detail_declares_404` | 详情接口声明了 404，且引用 `ErrorResponse` |
| `test_create_user_declares_409` | 创建用户声明了 409 |
| `test_login_declares_401` | 登录声明了 401 |
| `test_error_response_matches_schema` | 真实 404 返回 `{detail: str}`，与声明一致 |

最后一个最重要——**它防止文档和实现漂移**。

## 6.6 让文档更好用的几个细节

| 做法 | 效果 |
| --- | --- |
| `tags=["users"]` | 文档里按业务分组，不混在一起 |
| `summary="用户详情(带缓存)"` | 列表里一眼看出这个接口做了什么 |
| `Field(description=...)` | 每个字段有说明，前端不用问 |
| `response_model` | 响应裁剪 + 文档结构 |
| `responses={...}` | 错误码和错误格式 |
| `app = FastAPI(title=..., description=...)` | 文档首页有项目介绍 |

## 6.7 常见错误

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 文档里没有 404 | 只 `raise` 了，没声明 `responses` | 加 `responses={404: {...}}` |
| 文档写了但实际不一致 | 改代码时忘了同步 `responses` | 加契约测试 |
| `/docs` 打不开 | 生产环境关了 `docs_url` | 检查 `FastAPI(docs_url=None)` |
| 响应里字段比文档多 | 没有 `response_model` | 加上，让 FastAPI 裁剪 |
| 参数说明是空的 | `Query` 没写 `description` | 补上 |
| `response_model` 报字段缺失 | ORM 对象缺字段或名字不符 | 用 DTO 转换（见第四章） |

## 6.8 本章小结

1. `/docs` 由装饰器参数、函数签名、Pydantic 模型三部分自动生成。
2. `Query(le=50)` 这类约束会自动写进文档，前端不用猜。
3. **代码里 `raise` 的错误不会出现在文档里**，只有 200 和 422 是自动的。
4. 用 `responses={404: {"model": ErrorResponse}}` 把错误契约补上。
5. 契约必须和真实返回一致，否则比没文档更糟。
6. 用测试检查"文档里声明了 404"和"真实返回格式"，防止漂移。
7. 项目已给 3 个接口加上错误声明，并补了 5 个契约测试。
