# Docker 第一章 · 容器与编排入门

## 1.1 学习目标

前面三个部分讲的是"怎么把代码写好"，这一章讲"**怎么让别人一条命令跑起来**"。学完应该能做到：

1. 说清镜像和容器的区别
2. 看懂并会写 `Dockerfile`（含多阶段构建）
3. 会用 `docker compose` 一次起多个服务
4. 理解 `healthcheck` / `depends_on` / 端口映射 / 数据卷
5. 能把 `project/` 打包成"clone 下来就能跑"的镜像

> **本章的读法**：三个案例都是 Python 脚本，通过 `docker` CLI 观察真实容器。
> 正文里的输出来自本机实测，你可以自己跑一遍对照。

## 1.2 为什么需要容器

### 1.2.1 "在我机器上能跑"

没有容器时，别人拿到你的项目要经历：

```plain
   装 Python 3.12        （版本不对就报错）
   装 MySQL 8.0          （端口冲突、密码不同）
   建库、跑迁移           （忘了就报 Table doesn't exist）
   装依赖                 （pip 卡住、版本冲突）
   启动                   （命令记错就 blank）
```

**四步里任何一步出错，你的项目在别人眼里就是"跑不起来"。**

有容器之后：

```bash
git clone ...
cd project
docker compose up -d --build
```

两分钟，`http://127.0.0.1:8000/docs` 就能打开。

> **通俗理解**：以前是"把菜谱给你，你自己买菜、备锅、控火"；现在是"把整个厨房打包给你"。

### 1.2.2 容器和虚拟机的区别

| | 虚拟机 | 容器 |
| --- | --- | --- |
| 隔离层次 | 硬件级，各自跑一个完整 OS | 进程级，共享宿主内核 |
| 启动时间 | 分钟级 | 秒级 |
| 体积 | GB 级 | MB 级 |
| 适合 | 需要不同内核/强隔离 | 打包应用及其依赖 |

## 1.3 镜像与容器

### 1.3.1 三个概念

```plain
   Dockerfile  ──构建──►  镜像(image)  ──运行──►  容器(container)
   一份说明书            一个只读模板          一个跑起来的进程
```

案例文件：`docker_notes/ch01/code/02_container_lifecycle.py`

```plain
--- ② 跑一个容器: 执行 echo 后退出 ---
    退出码: 0
    容器输出: hello from container

--- ④ 删掉容器, 镜像还在 ---
    容器: (已删除)
    镜像: alpine:3  7.8MB
```

**关键**：删容器不影响镜像，所以重建环境很快——不用重新下载。

### 1.3.2 常用命令

| 命令 | 干什么 |
| --- | --- |
| `docker images` | 本地有哪些镜像 |
| `docker ps` | 正在跑的容器 |
| `docker ps -a` | 包括已退出的 |
| `docker run` | 从镜像起一个容器 |
| `docker stop` / `rm` | 停 / 删容器 |
| `docker logs <name>` | 看容器输出 |
| `docker exec -it <name> sh` | 进容器里敲命令 |

## 1.4 Dockerfile 怎么写

本项目的 `project/Dockerfile`，逐段解释：

```dockerfile
FROM python:3.12-slim AS builder      # ① 基础镜像：官方精简版 Python
WORKDIR /app                          # ② 工作目录
ENV PIP_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple   # ③ 用国内镜像
COPY requirements.txt .               # ④ 先只拷依赖清单
RUN pip install --prefix=/install -r requirements.txt        # ⑤ 装依赖
```

**为什么先 COPY requirements 再 COPY 源码**：Docker 按层缓存，依赖没变时这一层直接命中，改代码不会重新装一遍包（否则每次构建都要 40 秒）。

```dockerfile
FROM python:3.12-slim AS runtime      # ⑥ 第二个阶段：只带运行时需要的东西
COPY --from=builder /install /usr/local                  # ⑦ 把装好的包搬过来
COPY . .                              # ⑧ 再拷源码
USER appuser                          # ⑨ 非 root 运行
HEALTHCHECK ... CMD python -c "..."   # ⑩ 健康检查
CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

| 指令 | 作用 | 常见坑 |
| --- | --- | --- |
| `FROM` | 基础镜像 | 用 `slim` 减小体积 |
| `WORKDIR` | 容器内工作目录 | 用绝对路径 |
| `COPY` | 拷贝文件 | 配合 `.dockerignore` 排除 `.venv` |
| `RUN` | 构建时执行 | 多个命令用 `&&` 合并，减少层 |
| `ENV` | 环境变量 | 密码**不要**写死在这里 |
| `USER` | 切用户 | 不用 root |
| `CMD` | 启动命令 | 不要加 `--reload` |
| `HEALTHCHECK` | 健康检查 | 没有它，`depends_on` 的 `service_healthy` 没法用 |

### 1.4.1 多阶段构建为什么好

```plain
   阶段一(构建): 有 pip、有编译器等工具      体积大
   阶段二(运行): 只拷装好的包 + 源码          体积小
```

本项目的应用镜像 **333MB**；如果单阶段构建（把 pip 缓存和临时文件都留下），通常 500MB 以上。

> **通俗理解**：像装修——施工阶段用脚手架，交付时把脚手架拆掉，只留成品。

### 1.4.2 用 `.dockerignore` 排除不该进镜像的东西

```plain
.git
.venv
__pycache__
.env          ← 最重要：密钥不能打进镜像
tests
```

`COPY . .` 会把整个目录塞进镜像，没有 `.dockerignore` 的话，`.env` 里的数据库密码就跟着镜像跑了。

## 1.5 docker-compose：一次起三个服务

单个 `docker run` 只能起一个容器，而我们的应用需要 MySQL + Redis + 应用本身。

`project/docker-compose.yml` 的结构：

```yaml
services:
  mysql:
    image: mysql:8.0
    environment:
      MYSQL_ROOT_PASSWORD: ${MYSQL_ROOT_PASSWORD:-rootpass}
      MYSQL_DATABASE: learn_mysql
    ports: ["3307:3306"]                  # 宿主机 3307 -> 容器 3306
    volumes: [mysqldata:/var/lib/mysql]   # 数据持久化
    healthcheck: ...

  redis:
    image: redis:7-alpine
    ports: ["6380:6379"]
    healthcheck: ...

  app:
    build: .
    environment:
      MYSQL_HOST: mysql                   # ← 用服务名当主机名
      REDIS_HOST: redis
    depends_on:
      mysql: {condition: service_healthy}
      redis: {condition: service_healthy}
    command: sh -c "alembic upgrade head && uvicorn ..."
```

### 1.5.1 四个关键点

**① 端口映射 `宿主机:容器`**

```plain
   3307:3306   本机已有 MySQL 占着 3306, 所以对外用 3307
   6380:6379   同理, 本机 Redis 占着 6379
   8000:8000   应用端口没冲突, 直接用
```

容器**内部**端口始终是 3306 / 6379，应用连的是容器名，不受宿主机端口影响。

**② 用服务名互联**

```plain
   app 容器里连 mysql:3306   ← 不是 localhost
```

`localhost` 在容器里指容器自己，连不到隔壁容器。compose 会自动把服务名解析成容器 IP。

**③ depends_on + healthcheck**

```yaml
depends_on:
  mysql:
    condition: service_healthy
```

只写 `depends_on: [mysql]` 只能保证"容器启动了"，但 MySQL 启动到能接受连接还有几秒。加 `condition: service_healthy` 才会等健康检查通过。

**④ volume 让数据不丢**

```yaml
volumes: [mysqldata:/var/lib/mysql]
```

`docker compose down` 停容器，数据还在；只有 `down -v` 才会连数据一起删。

```bash

```

首次构建约 1 分半（拉基础镜像 + 装依赖），之后改代码重建只要几秒。

## 1.7 常用命令

| 命令 | 作用 |
| --- | --- |
| `docker compose up -d --build` | 构建并后台启动 |
| `docker compose ps` | 看服务状态 |
| `docker compose logs -f app` | 跟踪应用日志 |
| `docker compose exec app sh` | 进应用容器 |
| `docker compose stop` | 停止，容器保留 |
| `docker compose down` | 停止并删除容器，**数据保留** |
| `docker compose down -v` | 连数据卷一起删 |
| `docker compose build --no-cache app` | 不用缓存重建 |

## 1.8 常见错误

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| `permission denied ... dockerDesktopLinuxEngine` | Docker Desktop 没启动 / 命名管道没权限 | 启动 Docker Desktop；换普通终端重试 |
| `port is already allocated` | 宿主机端口被占 | 改映射，如 `3307:3306` |
| 应用连不上 MySQL | 用了 `localhost` | 改成服务名 `mysql` |
| `Table doesn't exist` | 没跑迁移 | 启动命令加 `alembic upgrade head` |
| 镜像很大 | 没多阶段构建 / 没 `.dockerignore` | 两阶段 + 排除 `.venv` |
| 改了代码没生效 | 用的是旧镜像 | `docker compose up -d --build` |
| 数据莫名丢失 | 用了 `down -v` | 只 `down`，别加 `-v` |
| 应用启动就退出 | 启动命令报错 | `docker compose logs app` 看原因 |

## 1.9 本章小结

1. 容器解决的是"环境不一致"问题：把应用和它的依赖一起打包。
2. Dockerfile 是**说明书**，构建出**镜像**，跑起来才是**容器**。
3. **多阶段构建**把编译工具留在构建阶段，镜像从 500MB+ 降到 333MB。
4. **先 COPY 依赖清单再 COPY 源码**，让依赖层能命中缓存。
5. `.dockerignore` 要排除 `.env`——密钥不能进镜像。
6. compose 用**服务名**做主机名，用 `healthcheck + condition` 保证启动顺序。
7. 启动命令里带 `alembic upgrade head`，空库也能一键跑起来。
8. 实测：三个容器 healthy，迁移自动执行，注册/登录/缓存/文档全部可用。
